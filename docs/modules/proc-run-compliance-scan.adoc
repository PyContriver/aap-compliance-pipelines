= Running a compliance scan

[role="_abstract"]

Use the compliance pipelines plugin to scan managed hosts against a compliance standard, review findings, build a remediation profile, and apply remediations through {ControllerName} job templates.

.Prerequisites

* A compliance pipeline is configured on your {PlatformNameShort} instance. For more information, see xref:proc-configure-compliance-pipeline_{context}[Configuring a compliance pipeline].
* At least one compliance profile is registered in the plugin *Settings* tab.
* Target hosts are added to an inventory in {ControllerName} and are accessible over the Receptor mesh.
* The compliance {ExecEnvShort} is registered and available on your execution nodes.

.Procedure

. Register a compliance profile.
+
If you have not already registered a compliance profile, navigate to the *Settings* tab in the compliance plugin.
+
Click *Add Profile* and configure the following:
+
[cols="1,2", options="header"]
|===
|Field
|Description

|Profile Name
|A descriptive name for the compliance standard (for example, `RHEL 9 DISA STIG V2R8`).

|Assessment Job Template
|The job template in {ControllerName} that runs the compliance assessment (for example, `compliance-run-oscap`).

|Execution Environment
|The {ExecEnvShort} containing the scanner and compliance content.

|Framework
|The compliance framework identifier (for example, `DISA STIG`, `CIS Benchmark`).
|===
+
Click *Save*. The profile appears in the *Profiles* tab.
+
To edit an existing profile, click the edit icon (pencil) next to the profile row in the *Settings* tab. The edit dialog opens with the current values pre-populated. Make your changes and click *Update*.
+
Optionally, configure platform requirements for the profile by specifying the *OS Family*, *OS Version*, or *Device Type* fields. These constrain which hosts are valid targets for scans using this profile.

. Launch an assessment scan.
+
Navigate to the *New Scan* tab. Each compliance profile tile displays the canonical rule count from the compliance standard metadata (for example, 489 for DISA STIG RHEL 9). This number reflects the total rules in the standard and does not change based on scan results.
+
Configure the scan parameters:
+
.. Select the compliance profile to scan against.
.. Select or confirm the target inventory.
.. Optionally, set a host limit to scope the scan to specific hosts.
.. Click *Launch Scan*.
+
The plugin submits a job template launch request to {ControllerName}. You are redirected to the scan progress view.

. Monitor the scan progress.
+
The scan progress view displays the job status in real time. The plugin polls the {ControllerName} API for status updates.
+
Wait for the scan job to reach a terminal state (*Successful*, *Failed*, or *Canceled*).

. Investigate failed scans.
+
If the scan fails, the plugin fetches the real error details from the {ControllerName} job API and displays them in a scrollable error panel. The error details are cached in the database so they load instantly on subsequent views.
+
The error panel shows the `result_traceback` from the failed job, which typically includes SSH connection errors, credential failures, or playbook execution errors. This applies to both assessment scans and remediation jobs.
+
Click *Try Again* to return to the scan launcher and retry the scan.

. View scan results.
+
After the scan completes, navigate to the *Results* tab.
+
The results list shows all completed scans with the following information:
+
* Scan date and duration
* Compliance profile used
* Overall pass/fail ratio
* Number of hosts scanned
+
Click a scan result to open the detailed results viewer. The results viewer displays:
+
* Per-rule findings organized by severity (High, Medium, Low), viewable in two modes: *By Status* (pass/fail grouping) or *By Category* (Access Control, Audit, etc.)
* Pass, fail, error, and not-applicable counts
* Per-host breakdown of findings with actual vs. expected values
* *Export* button to download findings as CSV (for auditors and spreadsheets) or JSON (for tool integration)

. Build a remediation profile.
+
From the results viewer, click *Build Remediation*.
+
The remediation profile builder displays all failed rules from the scan. For each rule, you can:
+
.. *Toggle rules on or off* -- Select which rules to include in the remediation. Rules that may cause service disruption are flagged with a warning.
.. *Customize parameters* -- Override default remediation parameters for specific rules (for example, password length, audit log retention period).
.. *Set scope* -- Choose which hosts to remediate (all hosts from the scan, or a subset).

. Save the remediation profile.
+
After configuring your rule selections and parameters, enter a name and description for the remediation profile.
+
Click *Save Remediation*. The saved remediation appears in the *Remediations* tab and can be reused for future remediation runs.

. Reuse an existing remediation profile.
+
If you have already saved a remediation profile for the same compliance standard, you can apply it to new scan results instead of building a new one.
+
From the results viewer, click *Use Existing Remediation*. The plugin opens the *Remediations* tab with a filter applied that shows only remediation profiles matching the current compliance standard. For example, if you are viewing DISA STIG scan results, only STIG remediation profiles are displayed.
+
A filter chip at the top of the list shows the active filter (for example, *DISA STIG*). Click the clear button on the chip to remove the filter and see all remediation profiles.

. Apply the remediation.
+
From the *Remediations* tab, select the remediation profile you saved and click *Launch Remediation*.
+
The *Launch Remediation* dialog opens and prompts you to select a target inventory. After you select an inventory, the system checks whether a completed assessment scan exists for this profile and inventory combination. This scan is the _authoritative scan_ that determines which hosts need remediation.
+
** If a completed assessment scan exists, the dialog shows the scan date and you can proceed with the launch.
** If no completed assessment scan exists, the dialog displays a *Run a Scan First* button. Clicking this button opens the scan launcher pre-populated with the correct compliance profile and inventory so you can run an assessment before remediating.
+
Alternatively, from the results viewer, click *Execute Remediation* to launch the remediation immediately without saving a profile. In this case, the scan you are viewing serves as the authoritative scan.
+
The plugin launches the remediation job template in {ControllerName}, passing the selected rules as job tags and custom parameters as extra variables. The authoritative scan is recorded as the _informing scan_ on the execution record for audit traceability.
+
[IMPORTANT]
====
Remediation modifies the configuration of target hosts. Review the selected rules and parameters before executing. Ensure you have a rollback plan for production systems.
====

. Run a verification scan.
+
After the remediation completes, click *Run Verification Scan* from the remediation completion view, or return to the *New Scan* tab and launch a verification scan against the same hosts and compliance profile.
+
The verification scan results include a *comparison view* that displays side-by-side gauges showing the pass rate before and after remediation.

.Verification

* In the *Results* tab, confirm that the verification scan shows an improved pass rate compared to the initial assessment scan. The comparison gauges display the before and after scores automatically.
* For each rule that was remediated, verify that the finding status changed from *fail* to *pass* in the verification scan results.
* Optionally, export the verification scan findings as CSV or JSON using the *Export* button for audit documentation.
