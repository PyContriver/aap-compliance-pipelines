= Running an OpenSCAP compliance scan

[role="_abstract"]

Run an OpenSCAP-based compliance scan against RHEL 9 target hosts using a single job template. The `run_oscap.yml` playbook contains two plays in one JT: Play 1 executes `oscap xccdf eval` on each target host and fetches the XCCDF result XML back to the execution node; Play 2 normalizes the results to Common Findings Format (CFF) JSON on localhost (same container). Because both plays run in the same container, fetched files are available to the normalize step without cross-container file sharing.

Remediation is launched separately as a standalone job template, not as part of the assessment.

.Prerequisites

* {PlatformNameShort} {PlatformVers} or later is deployed and accessible.
* The compliance {ExecEnvShort} is built and registered in {ControllerName}. The {ExecEnvShort} must include `scap-security-guide` and `openscap-scanner`.
* Target hosts are running RHEL 9 and are registered in an inventory accessible to {ControllerName}.
* SSH credentials with `become` privileges are configured for the target hosts.
* The compliance content project is synced in {ControllerName}.

.Procedure

. Verify the {ExecEnvShort} contains the required SCAP content.
+
The compliance {ExecEnvShort} must contain the SCAP datastream and the CaC remediation playbook. Verify these files exist in the image:
+
[source,bash]
----
podman run --rm compliance-stig-rhel9:latest \
  ls /usr/share/xml/scap/ssg/content/ssg-rhel9-ds.xml \
     /usr/share/scap-security-guide/ansible/rhel9-playbook-stig.yml
----
+
If either file is missing, rebuild the {ExecEnvShort} with `scap-security-guide` in the system dependencies.

. Create the assessment job template in {ControllerName}.
+
Navigate to *Templates* > *Add* > *Add Job Template* and set the following values:
+
[cols="1,2", options="header"]
|===
|Field
|Value

|Name
|`compliance-run-oscap`

|Job Type
|Run

|Inventory
|`compliance-rhel9-inventory`

|Project
|`compliance-content`

|Playbook
|`collections/ansible_collections/security/compliance_rhel9_stig/playbooks/run_oscap.yml`

|Execution Environment
|`Compliance STIG RHEL 9`

|Credentials
|Machine credential with SSH + become access

|Prompt on Launch: Inventory
|Enabled
|===
+
[NOTE]
====
The `run_oscap.yml` playbook contains two plays: Play 1 scans targets via SSH, and Play 2 normalizes results on localhost. Both run in the same container, so no separate normalize JT is needed.
====

. Launch a test scan.
+
Navigate to *Templates*, locate `compliance-run-oscap`, and click *Launch*. Select a target inventory and click *Launch*.
+
Monitor the job. Play 1 runs `oscap xccdf eval` on each target host and fetches results. Play 2 normalizes the results to CFF JSON on localhost.

. Verify the scan results.
+
After the job completes, check the job output for the normalize task summary:
+
[source]
----
Normalized 3 hosts, 1098 findings (840 pass, 216 fail, 0 error, 42 N/A).
----
+
The compliance plugin reads the `compliance_report` Ansible fact from job events and displays findings in the Results tab.

.Verification

* The job completes with a successful status.
* The normalize task output shows the expected host count and finding totals.
* Findings appear in the compliance plugin Results tab with rule metadata (title, description, fix text, severity, STIG ID).
* Rule IDs in the findings match CaC remediation tags (for example, `sshd_set_keepalive_0`, `accounts_tmout`).
